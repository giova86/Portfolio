Playlist Downloader

Web app to download playlists from YouTube or Spotify quickly, easily, and with the best format and quality options.

Python Streamlit

Overview

Playlist Downloader is a Streamlit web app that downloads whole playlists as tagged MP3 files, from either Spotify or YouTube. The interface is two tabs and one field: paste a playlist URL, press Download, and watch the per-track progress; an "Open Download Folder" button opens the destination directly in the host OS file manager when the run finishes.

The Spotify path is the more involved of the two, because Spotify does not serve audio. The app authenticates against the Spotify Web API with spotipy using client-credentials from a local config.ini, walks the playlist and writes out a reference file of every track with its title, artist, album and cover-art URL. Each track is then resolved to a YouTube result by searching "artist – title" through youtube-search, with up to ten retries per track before it is skipped. The chosen video is downloaded with yt-dlp at best available audio quality and converted to 192 kbps MP3 by ffmpeg. The track is then re-tagged from the Spotify metadata rather than from YouTube's: mutagen writes the ID3 frames and embeds the album artwork fetched from Spotify as an APIC frame, so the resulting library has correct titles, artists and covers instead of whatever the uploader happened to name the video.

The YouTube path is direct: the playlist is expanded with yt-dlp, each entry is downloaded as best audio and converted to MP3, with a progress hook reporting each track's state back into the Streamlit placeholder as the run proceeds. Downloads are organised into a folder named after the playlist under downloads/.

For long Spotify playlists the app can parallelise: a multicore handler splits the track list into segments and downloads them across multiple processes, keeping a configurable number of cores free as buffer. Progress is streamed live into the page through Streamlit placeholders, invalid URLs are caught and reported as toasts rather than tracebacks, and the folder-opening helper dispatches on the operating system. The whole UI is custom-styled with injected CSS over a pirate-themed header.

Key features

  • Two sources, one interface — Spotify and YouTube playlists are handled in separate tabs of the same app, both producing MP3 files in a folder named after the playlist.
  • Spotify-accurate metadata — tracks are resolved to YouTube for the audio, but titles, artists and album art come from the Spotify API, so the tags are right even when the video's own title is not.
  • Embedded album artwork — the cover image is fetched from Spotify and written into each MP3 as an ID3 APIC frame with mutagen.
  • Automatic YouTube matching with retries — each Spotify track is searched as "artist – title" with up to ten attempts before being skipped, so one bad lookup doesn't abort the playlist.
  • 192 kbps MP3 conversion — yt-dlp pulls best available audio and ffmpeg post-processors handle both the MP3 encoding and the metadata write-back.
  • Multicore downloading — long Spotify playlists are split into segments and processed across multiple cores, with a configurable buffer of cores left free and an optional cap.
  • Live per-track progress — a Streamlit placeholder is updated with the track currently downloading and a yt-dlp progress hook feeds status back during the transfer.
  • Open-folder shortcut — a button opens the downloads directory in the host file manager, dispatching on the detected operating system.
  • Resilient input handling — malformed or non-playlist URLs are caught and surfaced as toast warnings instead of stack traces, and Spotify playlist IDs are extracted from full share links.
  • External credential configuration — Spotify client id, secret and username live in a git-ignored config.ini created from a distributed template, keeping secrets out of the code.
  • Custom-styled UI — injected CSS and a themed header replace the default Streamlit look.

Tech stack

Python

Orchestrates the whole pipeline: playlist expansion, the reference-file format, the search/download /tag loop, the multicore segmentation and the OS-specific folder opener.

Streamlit

Provides the two-tab UI, the URL inputs, the buttons and the live status placeholders, plus the injected CSS that restyles the page.

spotipy

Authenticates with client credentials against the Spotify Web API and walks the playlist to collect each track's title, artist, album and cover-art URL.

yt-dlp

Downloads the audio for both paths — the matched YouTube video for a Spotify track, or the playlist entries directly — and runs the ffmpeg post-processors.

youtube-search

Resolves each Spotify track to a YouTube URL by querying "artist – title" and taking the best result, with a retry budget per track.

mutagen

Writes the ID3 tags on the finished MP3 and embeds the Spotify album artwork as an APIC frame.

ffmpeg

Extracts and encodes the audio to 192 kbps MP3 and writes the container metadata, invoked through yt-dlp's post-processor chain.

multiprocessing

Splits long playlists into per-core segments so several tracks download in parallel, with a configurable core budget.
