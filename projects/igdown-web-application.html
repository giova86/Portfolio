IGDown - Web Application

Web App that allow download reels from Instagram.

Python Javascript React FastAPI HTML

Overview

IGDown is a self-hosted web application for downloading Instagram Reels as MP4 video or MP3 audio. It runs entirely on the user's own machine — no ads, no upload limits, no third-party service in the middle — and is started with a single start.sh that checks the toolchain, provisions both environments on first run, and launches the FastAPI backend on port 8000 and the Vite dev server on port 5173 together.

The interesting part is the job model. A download is not a blocking HTTP request: POST /api/download validates the URL, registers a job and immediately returns a job_id. The actual work is handed to a ThreadPoolExecutor capped at four workers, with job state kept in memory behind a threading.Lock. The browser then opens GET /api/progress/{job_id}, a Server-Sent Events stream that pushes status, percentage, transfer speed and ETA as yt-dlp reports them, and closes itself when the job reaches a terminal state. Only once the status is done does the frontend hit GET /api/file/{job_id}, which returns the file as an attachment. The upshot is a progress bar that reflects the real download rather than an animation, and a UI that never freezes on a long reel.

The backend is a properly separated FastAPI app — models.py for the Pydantic request and response schemas, one router per endpoint under routes/, and the yt-dlp integration, job registry and cleanup isolated in services/downloader.py — with a pytest suite covering the downloader, the models and the routes. Files are deleted automatically ten minutes after completion, so the machine doesn't accumulate downloads, and an invalid Instagram link is rejected with a 422 before any work starts.

The frontend is React with TypeScript on Vite. The download flow lives in a single useDownload hook implemented as an SSE state machine, feeding a small set of components — a download card, a progress bar, a toast system and a theme toggle. Light and dark themes are driven by CSS custom properties and persisted in localStorage, URL errors surface inline as you type, and the Vite dev server proxies /api to the backend so the whole thing behaves as one origin in development.

Key features

  • Reels as MP4 or MP3 — the same URL can be pulled as video or extracted to audio, with ffmpeg handling the MP3 conversion server-side.
  • Real-time progress over SSE — a Server-Sent Events stream pushes percentage, transfer speed and ETA straight from yt-dlp's progress hook, and terminates itself when the job finishes or fails.
  • Non-blocking job model — the download request returns a job_id immediately and the work runs in a four-worker ThreadPoolExecutor, with shared job state guarded by a threading.Lock.
  • Automatic cleanup — finished files are deleted ten minutes after completion, so a long-running instance never fills the disk.
  • URL validation with inline feedback — non-Instagram or malformed links are rejected with a 422 before a job is created, and the error is shown next to the field rather than as a dead end.
  • Dark / light theme — a toggle backed by CSS custom properties, persisted in localStorage across sessions.
  • One-command startup — start.sh verifies Python ≥ 3.9, Node ≥ 18 and ffmpeg, creates the virtualenv and installs both dependency sets on first run, then starts backend and frontend together and stops them together on Ctrl+C.
  • Tested backend — a pytest suite covers the downloader service, the Pydantic models and the HTTP routes.
  • Clean separation — Pydantic schemas, one router per endpoint and the yt-dlp integration each live in their own module, so the download engine can be swapped without touching the API surface.
  • Fully local — nothing leaves the machine except the request to Instagram itself: no account, no tracking, no third-party download service.

Tech stack

Python

Powers the backend: the job registry, the thread-pool execution model, the progress hook that feeds the SSE stream and the scheduled cleanup of finished files.

FastAPI

Exposes the three endpoints (create job, stream progress, fetch file), validates requests through Pydantic models, and manages startup/shutdown through the lifespan hook.

yt-dlp

The actual download engine, wrapped in services/downloader.py; its progress callback is what produces the percentage, speed and ETA the UI displays.

Server-Sent Events

A one-way stream from server to browser carrying job status updates — lighter than WebSockets for this shape of problem, and it closes itself when the job reaches a terminal state.

React + TypeScript

Builds the interface around a useDownload hook implemented as an SSE state machine, with typed components for the download card, progress bar, toasts and theme toggle.

Vite

Provides the dev server and build pipeline, and proxies /api to the FastAPI backend so frontend and backend share one origin during development.

ffmpeg

Extracts and encodes the audio track when a reel is requested as MP3.

pytest

Covers the downloader service, the request/response models and the API routes.
