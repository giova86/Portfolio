LLM Wiki - Web Application

Second brain based on Karpathy's guidelines

LLM Ollama Python Javascript React FastAPI

Overview

LLM-Wiki is a full-stack implementation of Andrej Karpathy's LLM-Wiki concept: a "second brain" that deliberately rejects chunk-and-embed RAG. Instead of slicing documents into fragments and retrieving them by vector similarity, the LLM acts as writer, editor and linter over a flat directory of clean Markdown pages. New sources are merged into existing pages rather than indexed as disconnected chunks, so knowledge compounds — and what you end up with is a plain-text wiki you can open in any editor, Obsidian included, not an opaque vector database.

Storage is three layers under data/. raw/ holds the uploaded sources, immutable and never modified by the app. wiki/ is the knowledge base itself: one topic per Markdown file, strict slug filenames, # Title always on the first line, cross-links in [[slug]] syntax, plus two automatically maintained navigation pages — index.md, a categorised catalogue with a one-line summary per page, and log.md, a chronological activity record. config.json holds connection settings and the inference profiles.

Three pipelines operate on that store. Ingest extracts text from a dropped .pdf, .docx, .md, .txt or .json, has the model atomicise it into topics, then merges each topic into an existing page or creates a new slug, and finally revises index.md and appends to log.md. Lint is a periodic health pass: it repairs missing titles and broken [[links]], flags orphan pages, deduplicates and merges overlapping pages, inserts missing cross-references and reports what it did. Chat answers questions strictly from the wiki — with no vector store anywhere: the model reads index.md to decide which pages are relevant, then reads those pages in full, and cites its sources as clickable [[slug]] badges that pop the exact page open.

Because ingest/lint and chat want opposite sampling behaviour, the app runs two inference profiles over the same model: profile A (processing) at temperature 0.1, top-k 10, top-p 0.1 for deterministic editing, and profile B (conversational) at 0.7 / 40 / 0.9 for fluent answers. Both are editable per-parameter in Settings. Any OpenAI-compatible endpoint works — LM Studio and Ollama presets for fully local operation, or any custom base URL including hosted providers — switchable at any time, and top_k is passed via extra_body so providers that ignore it still work. Prompts ask the model to wrap its output in a ```markdown fence and the backend extracts only that block, which discards the chain-of-thought that smaller local and reasoning models emit.

The FastAPI backend is cleanly modularised — config store, LLM client with profile routing, text extraction, the wiki page store, SQLite chat history, an ingest manifest, all prompts in one file, the pipelines, and one router per resource — and pipeline runs stream their logs and progress over SSE rather than blocking the UI. The React frontend gives three pages (Settings, Workspace, Chat) with full page and file management, a light/dark theme, and a logo that swaps with it. A single start.sh builds the venv, installs both sides, frees ports 8000/5173 and launches everything.

Key features

  • No vector database — retrieval works by having the model read a maintained index.md catalogue to pick pages, then read those pages in full; there are no embeddings, no chunks and no similarity search anywhere in the system.
  • Knowledge that compounds — ingesting a new source merges its content into existing pages instead of appending another isolated fragment, so a topic gets richer rather than duplicated.
  • Ingest pipeline — PDF, DOCX, Markdown, TXT and JSON are extracted, atomicised into topics by the LLM, merged or created as slugged pages, and reflected into index.md and log.md.
  • Lint pipeline — a maintenance pass that fixes missing titles and broken [[links]], flags orphans, deduplicates overlapping pages, inserts missing cross-references and produces a report.
  • Grounded chat with citations — answers are synthesised strictly from wiki pages and carry clickable [[slug]] citation badges that open the exact source page in a modal.
  • Dual inference profiles — a strict low-temperature profile for ingest and lint and a fluid higher-temperature one for chat, each with its own temperature, top-k, top-p and penalties, fully editable in Settings.
  • Any OpenAI-compatible backend — LM Studio and Ollama presets for running entirely offline on local hardware, or any custom base URL including hosted providers, with a "fetch models" button to populate the model list.
  • Markdown fence extraction — the backend keeps only the ```markdown block from each response, so chain-of-thought output from small local or reasoning models never leaks into the wiki.
  • Obsidian-compatible store — flat Markdown files with [[slug]] links open natively as an Obsidian vault, and empty dangling-link stubs are ignored rather than listed as phantom pages.
  • Full content management — every wiki page and raw source can be searched, viewed, edited (pages) or downloaded (sources) and deleted from the UI, with an ingest manifest tracking what has already been processed.
  • Live pipeline progress over SSE — runs stream their logs and a progress bar to the browser instead of blocking, and a second run of the same kind is rejected with a 409.
  • Context-window budgeting — the configured context size is used to decide how much document or page text fits into a single prompt.
  • Persistent chat history — conversations are stored in SQLite and can be listed, reopened and deleted.
  • Light/dark theme — class-based, persisted and broadcast by event, with a logo that swaps to match.

Tech stack

Python

Implements the backend as focused modules: the dual-profile config store, the wiki page/index/log store, text extraction, the ingest manifest, the prompt library and the two pipelines.

FastAPI

Serves the /api surface — settings, files, wiki pages, pipelines and chats — one router per resource, with SSE endpoints for pipeline progress and Swagger docs at /docs.

OpenAI-compatible LLM client

A single client with profile routing and JSON coercion, pointed at LM Studio, Ollama or any hosted provider; top_k is passed through extra_body so providers that don't support it degrade cleanly.

Ollama / LM Studio

The local inference backends the app is designed around, letting the entire second brain — sources, pages and model — stay on the user's own machine.

Markdown as the data layer

The wiki is the storage format: slugged files, # Title first lines, [[slug]] cross-links and generated index.md / log.md navigation pages — readable, diffable and editable outside the app.

SQLite

Stores chat conversations and their messages, the only part of the system that isn't plain files.

React

Builds the three-page frontend — Settings, Workspace and Chat — with Markdown rendering, citation badges, wiki and raw-file modals, and a persisted light/dark theme.

Server-Sent Events

Streams pipeline logs and progress to the browser so ingest and lint runs are observable while they happen.

Document extractors

PDF, DOCX, Markdown, TXT and JSON parsers normalise every uploaded source into plain text before the LLM ever sees it.
