Overview

LLM-Wiki is a full-stack implementation of Andrej Karpathy's LLM-Wiki idea: a "second brain" that deliberately rejects the usual chunk-and-embed approach. Instead of slicing documents into fragments and retrieving them by similarity, the language model acts as writer, editor and linter of a wiki of Markdown pages.

Drop in a PDF, Word, Markdown, text or JSON document and the model splits it into topics, then merges each topic into an existing page or creates a new one, so knowledge compounds instead of piling up as isolated snippets. A periodic lint pass fixes broken links, flags orphan pages and merges duplicates.

Chat answers are built strictly from wiki pages and carry clickable citations that open the exact source page.

What it does

Knowledge base

  • One topic per Markdown file with cross-links between pages
  • Opens natively as an Obsidian vault
  • Every page and source can be searched, viewed, edited or deleted from the interface

Pipelines

  • Ingest: extract, split into topics, merge or create pages
  • Lint: repair links, deduplicate and add missing cross-references
  • Live progress with logs streamed to the browser

Chat

  • Answers grounded in the wiki with clickable citations
  • Persistent conversation history
  • Two inference profiles — strict for editing, fluid for conversation — editable in settings

Models

  • Runs fully offline with LM Studio or Ollama
  • Works with any compatible endpoint, including hosted providers
  • Reasoning noise from small models never leaks into the wiki

How it is built

Storage is split in three layers: immutable raw sources, the wiki itself, and an index and log that the model maintains. A FastAPI back end orchestrates the pipelines, keeps chat history in SQLite and adapts how much text goes into each prompt to the model's context window. The interface is a React application with light and dark themes.

Tech stack

Python

Implements the backend as focused modules: the dual-profile config store, the wiki page/index/log store, text extraction, the ingest manifest, the prompt library and the two pipelines.

FastAPI

Serves the whole API — settings, files, wiki pages, pipelines and chats — with live progress streaming and interactive documentation.

OpenAI-compatible LLM client

A single client with profile routing and JSON coercion, pointed at LM Studio, Ollama or any hosted provider; top_k is passed through extra_body so providers that don't support it degrade cleanly.

Ollama / LM Studio

The local inference backends the app is designed around, letting the entire second brain — sources, pages and model — stay on the user's own machine.

Markdown as the data layer

The wiki is the storage format: slugged files, # Title first lines, [[slug]] cross-links and generated index.md / log.md navigation pages — readable, diffable and editable outside the app.

SQLite

Stores chat conversations and their messages, the only part of the system that isn't plain files.

React

Builds the three-page frontend — Settings, Workspace and Chat — with Markdown rendering, citation badges, wiki and raw-file modals, and a persisted light/dark theme.

Server-Sent Events

Streams pipeline logs and progress to the browser so ingest and lint runs are observable while they happen.

Document extractors

PDF, DOCX, Markdown, TXT and JSON parsers normalise every uploaded source into plain text before the LLM ever sees it.
