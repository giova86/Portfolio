Dead Space - Mobile Application

A branching detective story: you are agent Kara Voss, with 24 real hours to unmask the killer of Colonel Hale.

Dart Flutter

Overview

Dead Space is a text-driven investigation game for Android and iOS. The player is special agent Kara Voss of the SGC investigative unit, called to the underground base inside Cheyenne Mountain after Colonel Marcus Hale is found dead — apparent cardiac arrest, but the preliminary examination says otherwise. Eight suspects are confined to the base, six areas can be searched, and the player has 24 real-world hours to name the killer before the trail goes cold.

Under the narrative is a small, data-driven story engine. The whole case lives in a single story.json file of 88 narrative nodes, each with its own text, background artwork, optional music track, list of choices and the clues that reaching it unlocks. A choice can declare requires_clue or requires_clues, so dialogue options and entire areas stay locked until the player has actually found the evidence that would let Kara ask that question. With 146 distinct clues in play, the case is genuinely a dependency graph rather than a linear script: interrogations open up investigations, investigations contradict alibis, and the accusation only sticks if the supporting evidence is in hand.

The interface is built around a detective's toolkit rather than a generic "next" button. A bottom action bar exposes Investiga (jump to one of the six areas: laboratory, stargate, control room, armoury, the colonel's quarters, xenobiology), Interroga (question a suspect) and Accusa (make the final call). A notebook screen, reachable from a badge in the header that flags newly found evidence, lists every clue collected so far, grouped and labelled by the area it came from. A live countdown in the header shows what is left of the 24 hours; when it hits zero the game routes to a dedicated timeout screen and the case is lost.

Presentation carries a lot of the atmosphere. Scene text is revealed with a typewriter animation, backgrounds and content cross-fade between nodes through coordinated opacity animations, and the soundtrack changes with the scene using a manual 30/40-step volume ramp so one track fades out while the next fades in instead of cutting. Progress — the start timestamp and the set of found clues — is written to shared_preferences, so the investigation survives closing the app; accusing the wrong person resets it.

Key features

  • Branching case file — 88 narrative nodes covering six searchable areas and eight suspects, all authored in a single JSON file so the story can be rewritten or replaced without touching a line of Dart.
  • Clue-gated progression — 146 clues are collected automatically as nodes are reached; options declaring requires_clue / requires_clues stay visibly locked until the player holds the matching evidence, turning the story into an evidence dependency graph.
  • 24-hour real-time countdown — a persistent timer, anchored to a start timestamp in shared_preferences, keeps running while the app is closed; a live HH:MM:SS readout sits in the header and running out routes the player to a dedicated mission-failed screen.
  • Detective action bar — dedicated Investigate, Interrogate and Accuse controls replace generic navigation, letting the player move directly between areas and suspects instead of walking back through the narrative.
  • Evidence notebook — a notes screen lists every clue found, grouped by the area or interrogation that produced it, with a badge on the header counting evidence the player has not read yet and a running "clues collected: n / total" figure.
  • Final accusation with consequences — each of the eight suspects has its own written accusation outcome; only one is the real culprit, a wrong call resets the investigation, and the correct one closes the case.
  • Typewriter narration and scene transitions — text is typed out character by character, while background image and content fade in and out in a coordinated sequence between nodes.
  • Adaptive soundtrack with crossfade — each node can declare its own music file; switching tracks ramps the current one down and the new one up in small volume steps rather than cutting, and tracks loop continuously.
  • Resumable investigation — the timer and the collected clue set are persisted locally, so the home screen can offer "continue" on a case already in progress or reset it and start over.
  • In-app briefing — a "how to play" section explains the mission, the investigation and interrogation mechanics, the clue and unlock system, the accusation rules and the countdown, without an external manual.
  • Defensive asset handling — missing images, missing audio files, unknown node ids and malformed JSON all fall back gracefully instead of crashing the scene.

Tech stack

Dart

Implements the story engine: the StoryNode / Option model, JSON parsing, the clue set and unlock checks, the accusation logic and the GameTimer that computes remaining time from a persisted start timestamp.

Flutter

Renders the whole experience — home screen, scene view with its typewriter text and fading background, area and suspect pickers, notebook, accusation panel and timeout screen — from one codebase on Android and iOS, using explicit animation controllers for every transition.

audioplayers

Plays the per-scene soundtrack on loop and provides the volume control used to crossfade between tracks when the narrative moves to a node with different music.

shared_preferences

Persists the game start time and the set of discovered clues, making the 24-hour countdown real (it elapses whether or not the app is open) and letting the player resume an investigation later.

collection

Provides the grouping and lookup helpers used to organise collected clues by their source area in the notebook view.

JSON story format

A declarative node format (id, text, image, music, options, cluesObtained) that keeps the case entirely in data — new scenes, suspects or whole cases are authored, not coded.
