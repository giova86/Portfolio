YTDown - Web Application

Web App that allow download audio/video (single or playlist) from YouTube.

Python Javascript React FastAPI HTML

Overview

YTDown is a self-hosted web app for downloading YouTube content from the browser — a single video or an entire playlist, as MP3 audio at 192 kbps or MP4 video at best available quality. It is deliberately a local tool rather than a service: no ads, no registration, no rate limits and no tracking, started with one ./start.sh that provisions both sides and brings up the FastAPI backend on port 8000 and the Vite frontend on port 5173.

The flow is built around inspecting before downloading. POST /api/info first resolves the URL into metadata — title, thumbnail, duration, and for a playlist the full track listing — which the frontend renders as a preview so the user can confirm what they're about to pull. Only then does POST /api/download/start kick off a background task and return a task_id. Progress arrives over a Server-Sent Events stream at /api/download/progress/{task_id}, fed directly by yt-dlp's progress hook, and the finished artefact is retrieved from /api/download/file/{task_id}. A playlist download is bundled server-side into a single ZIP archive, so grabbing forty tracks is still one click and one file.

The backend is a compact FastAPI application wrapping yt-dlp, with ffmpeg doing the audio extraction and format conversion, and it publishes interactive Swagger documentation at /docs — the API is usable on its own, not just as a private backend for the UI. The frontend is React on Vite, split into four focused components: a URL input, a video preview, a playlist track list and a download panel, over a clean dark theme. The Vite config proxies /api to port 8000 so the two halves behave as one origin in development.

Key features

  • Single video or full playlist — the same input accepts either; playlists are resolved into their track listing before anything is downloaded.
  • Audio or video — MP3 at 192 kbps via ffmpeg extraction, or MP4 at the best available quality.
  • Metadata preview first — /api/info returns title, thumbnail, duration and playlist contents so the user confirms the target before the download starts.
  • Playlists bundled as ZIP — every track of a playlist is packaged server-side into a single archive, so a forty-track download is still one file to save.
  • Real-time progress over SSE — a Server-Sent Events stream driven by yt-dlp's progress hook keeps the UI in step with the actual transfer instead of showing a placeholder spinner.
  • Background task model — the download runs detached and is addressed by task_id, so the HTTP request never blocks and the page stays responsive.
  • Interactive API docs — FastAPI's Swagger UI at /docs documents all four endpoints, making the backend usable independently of the web UI.
  • One-command startup — start.sh creates the virtualenv, installs Python and Node dependencies on first run, starts both servers and shuts them down cleanly together.
  • Component-split frontend — URL input, video preview, playlist tracks and download panel are separate React components over a dark theme, with Vite proxying /api to the backend.
  • Private by construction — everything runs locally; there is no account, no server logging and no third-party download service in the path.

Tech stack

Python

Implements the backend: URL resolution, the background download tasks, the per-task progress state and the ZIP bundling of playlist downloads.

FastAPI

Exposes the four endpoints (info, start, progress stream, file retrieval), handles the SSE response and auto-generates the Swagger documentation at /docs.

yt-dlp

The download engine — metadata extraction for the preview, the actual media transfer, and the progress callback that drives the SSE stream.

Server-Sent Events

Streams per-task progress from server to browser over a plain HTTP connection, avoiding the polling loop a REST-only design would need.

React

Builds the UI from four components — URL input, video preview, playlist track list and download panel — holding the task state that the SSE stream updates.

Vite

Dev server and bundler for the frontend, configured to proxy /api to the FastAPI backend on port 8000.

ffmpeg

Performs the audio extraction and the MP3 encoding at 192 kbps, and the muxing for video downloads.

Uvicorn

The ASGI server running the FastAPI app, launched by start.sh alongside the frontend dev server.
