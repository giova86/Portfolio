Wikimens - Mobile Application

Mobile app that allows you to guess the word the user searched on Wikipedia through secret notifications.

Dart Flutter Ntfy

Overview

Wikimens is a mentalism prop disguised as an ordinary Wikipedia browser. To the spectator holding the phone it is simply the Italian Wikipedia: a full-screen page with no toolbar, no menu, no settings and no branding of its own. They search for any word they like and read the article. Meanwhile the performer's own device receives a push notification containing exactly the word that was looked up — which is the whole trick.

The interception works in two complementary ways, because Wikipedia can be reached through either. A small JavaScript snippet is injected into every page after load; it attaches an input listener to Wikipedia's search fields and keeps the last typed value in window._wkLastSearch, re-scanning the DOM through a MutationObserver so it keeps working as the single-page navigation rewrites the header. In parallel, the WebView's onNavigationRequest delegate inspects every URL the page tries to load: SearchInterceptor pulls the query out of Special:Search / Special:Ricerca and index.php?search= URLs, and if that fails a fallback parses the article slug out of any /wiki/… path and turns it back into a readable title. A word is only transmitted if the injected listener confirms the spectator actually typed a search — so ordinary link-following inside an article does not fire.

Delivery goes through ntfy.sh: the word is POSTed as plain UTF-8 text to https://ntfy.sh/{topic}, with the word also set as the notification title so it is readable straight from the lock screen or a smartwatch. No account, no Firebase project and no server of the performer's own is required — subscribing the second device to the same topic is the entire setup.

Two details make it usable as a real routine rather than a demo. A configurable delay of 0 to 300 seconds defers the notification, so the performer's phone does not buzz the instant the spectator types — and so a mistyped search can be corrected before the alert lands. And a 3-second duplicate-suppression window discards the same word sent twice, which matters because Wikipedia's search flow can trigger several navigation events for a single query. Configuration itself is hidden: there is no settings button anywhere in the UI, and the panel for the ntfy topic and the delay only opens after five taps in the bottom-right corner within two seconds — an invisible 60×60 hit target the spectator will never find. Settings persist in shared_preferences, and the app builds for Android, iOS, macOS, Windows and Linux.

Key features

  • Indistinguishable from a real browser — it.wikipedia.org is loaded full-screen in a WebView with JavaScript enabled and no app chrome of any kind, so nothing on screen suggests the page is instrumented.
  • Keystroke-level search capture — an injected script attaches to Wikipedia's search inputs and records the typed query, re-attaching automatically via a MutationObserver as the page rewrites its own DOM.
  • URL-level interception — the navigation delegate extracts the query from Special:Search, Special:Ricerca and index.php?search= URLs, with an article-slug fallback that decodes /wiki/Some_Title back into "Some Title".
  • Search confirmation gate — a word is only sent when the injected listener confirms the user actively typed it, so following links inside an article does not generate spurious notifications.
  • ntfy.sh delivery — the captured word is posted as plain UTF-8 text to a user-chosen ntfy topic and carries the word as the notification title, readable from a lock screen or watch with no app to open.
  • Configurable 0–300 s delay — the notification can be deferred by up to five minutes, giving the spectator room to correct a typo and the performer control over when the reveal arrives.
  • Duplicate suppression — identical words captured within a 3-second window are discarded, absorbing the multiple navigation events a single Wikipedia search can produce.
  • Gesture-hidden settings — five taps in an invisible 60×60 region in the bottom-right corner within two seconds open a bottom sheet for the topic and the delay; the delay stepper accelerates from 1 to 5 to 20 seconds per tick when held.
  • Persisted, silent configuration — topic and delay are stored in shared_preferences; with no topic configured the app sends nothing at all and behaves as a plain Wikipedia browser.
  • Resilient by design — network failures in the send path are swallowed silently, so a dropped request can never surface an error dialog in front of the spectator.
  • Cross-platform — a single codebase targeting Android, iOS, macOS, Windows and Linux.

Tech stack

Dart

Implements the interception pipeline: SearchInterceptor's URL parsing, the article slug fallback, the duplicate-suppression window and the deferred-send timer that schedules the notification.

Flutter

Hosts the app as a single full-screen widget tree — WebView plus an invisible corner gesture detector — and provides the modal bottom sheet used for the hidden settings panel.

webview_flutter

Embeds Wikipedia with unrestricted JavaScript, exposes the onPageFinished hook used to inject the search listener, the onNavigationRequest delegate used to inspect URLs, and runJavaScriptReturningResult to read back the captured query.

Injected JavaScript

A guarded, idempotent snippet that binds an input handler to Wikipedia's search fields and re-scans the DOM through a MutationObserver, surviving the site's client-side navigation.

ntfy.sh + http

NtfyService posts the word to https://ntfy.sh/{topic} as text/plain; charset=utf-8 with a Title header, using a shared http.Client and swallowing every error so failures stay invisible.

shared_preferences

Stores the ntfy topic and the notification delay on-device, keeping the app stateless from the spectator's point of view while remembering the performer's configuration between sessions.
